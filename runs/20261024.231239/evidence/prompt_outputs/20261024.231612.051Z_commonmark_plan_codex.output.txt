# FEATURE: Emphasis

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parse CommonMark emphasis and strong emphasis in inline content. |
| Depends On  | FEATURE-CLI.md, FEATURE-THEMATIC-BREAKS.md, FEATURE-ATX-HEADINGS.md, FEATURE-SETEXT-HEADINGS.md, FEATURE-INDENTED-CODE.md, FEATURE-FENCED-CODE.md, FEATURE-HTML-BLOCKS.md, FEATURE-LINK-REFERENCE-DEFINITIONS.md, FEATURE-PARAGRAPHS.md, FEATURE-BLANK-LINES.md, FEATURE-BLOCK-QUOTES.md, FEATURE-LIST-ITEMS.md, FEATURE-LISTS.md, FEATURE-BACKSLASH-ESCAPES.md, FEATURE-CHARACTER-REFERENCES.md, FEATURE-CODE-SPANS.md |
| Provides    | CommonMark emphasis and strong emphasis |
| Consumes    | CommonMark inline content |

## Questions

- None.

## Purpose

Interpret `*` and `_` delimiter runs as emphasis or strong emphasis according to the CommonMark delimiter-run rules. Support nested spans, Unicode whitespace and punctuation, intraword `*` emphasis, the restrictions on intraword `_` emphasis, and the specified precedence and ambiguity rules.

## Parsing and rendering

- Determine left- and right-flanking runs from neighboring Unicode whitespace and punctuation.
- Apply the opener and closer rules for `*`, `_`, `**`, and `__`, including the rule of three.
- Use the smallest valid delimiter spans and minimize nesting where the rules require it. Preserve unmatched delimiter characters as text.
- Render emphasis with `<em>` and strong emphasis with `<strong>`. Parse their contents as inline content, including other emphasis constructs.
- Code spans, links, images, and HTML tags bind more tightly than emphasis.

# FEATURE: Links

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parse inline and reference-style CommonMark links. |
| Depends On  | FEATURE-CLI.md, FEATURE-THEMATIC-BREAKS.md, FEATURE-ATX-HEADINGS.md, FEATURE-SETEXT-HEADINGS.md, FEATURE-INDENTED-CODE.md, FEATURE-FENCED-CODE.md, FEATURE-HTML-BLOCKS.md, FEATURE-LINK-REFERENCE-DEFINITIONS.md, FEATURE-PARAGRAPHS.md, FEATURE-BLANK-LINES.md, FEATURE-BLOCK-QUOTES.md, FEATURE-LIST-ITEMS.md, FEATURE-LISTS.md, FEATURE-BACKSLASH-ESCAPES.md, FEATURE-CHARACTER-REFERENCES.md, FEATURE-CODE-SPANS.md, FEATURE-EMPHASIS.md |
| Provides    | Inline and reference links |
| Consumes    | Document link reference definitions |

## Questions

- None.

## Purpose

Parse inline links and full, collapsed, and shortcut reference links. Resolve reference labels against the document-wide definitions collected during block parsing.

## Link behavior

- Parse inline destinations in angle-bracket or balanced-parenthesis form, optional titles, escapes, and character references as specified.
- Match reference labels after Unicode case folding, trimming, and collapsing whitespace. The first matching definition wins.
- Support links with empty text or destinations when allowed by the syntax.
- Bracketed link text may contain balanced brackets and inline elements. Links cannot contain nested links; code spans, autolinks, and raw HTML tags bind more tightly than link brackets.
- Render destinations as `href` and optional titles as `title`, escaping attribute values for HTML. Render link text as inline HTML.
- Images use the same syntax but are specified and implemented by the image capability.

# FEATURE: Autolinks

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Convert valid URI and email autolinks into HTML links. |
| Depends On  | FEATURE-CLI.md, FEATURE-THEMATIC-BREAKS.md, FEATURE-ATX-HEADINGS.md, FEATURE-SETEXT-HEADINGS.md, FEATURE-INDENTED-CODE.md, FEATURE-FENCED-CODE.md, FEATURE-HTML-BLOCKS.md, FEATURE-LINK-REFERENCE-DEFINITIONS.md, FEATURE-PARAGRAPHS.md, FEATURE-BLANK-LINES.md, FEATURE-BLOCK-QUOTES.md, FEATURE-LIST-ITEMS.md, FEATURE-LISTS.md, FEATURE-BACKSLASH-ESCAPES.md, FEATURE-CHARACTER-REFERENCES.md, FEATURE-CODE-SPANS.md, FEATURE-EMPHASIS.md, FEATURE-LINKS.md, FEATURE-IMAGES.md |
| Provides    | URI and email autolinks |
| Consumes    | CommonMark inline content |
 
## Questions

- None.

## Purpose

Recognize valid absolute URI and email address autolinks enclosed in angle brackets. Render them as links whose visible text is the URI or address; email links use the `mailto:` scheme.

## Autolink rules

- URI schemes begin with an ASCII letter, contain 2–32 characters, and use only ASCII letters, digits, `+`, `.`, or `-`.
- URI contents exclude ASCII control characters, spaces, `<`, and `>`.
- Email autolinks follow the email address grammar in the CommonMark specification.
- Backslash escapes are not interpreted inside autolinks.
- Invalid autolinks remain ordinary text and are escaped as HTML text.
