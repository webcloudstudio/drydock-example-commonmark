# FEATURE: Fenced Code Blocks

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parses and renders CommonMark fenced code blocks. |
| Depends On  | FEATURE-CLI.md |
| Provides    | fenced code blocks |

## Questions

- None.

## Purpose

Recognize fenced code blocks using CommonMark 0.31.2 rules, preserving their literal content and rendering the opening fence’s first info-string word as the code language class.

## Behavior

- An opening fence is at least three backticks or tildes, preceded by no more than three spaces. Backticks and tildes cannot be mixed.
- A backtick fence’s info string cannot contain backticks. The trimmed info string’s first word, when present, produces `class="language-{word}"` on `<code>`.
- A closing fence uses the opening character, has at least the opening length, is indented by no more than three spaces, and has only spaces or tabs after it.
- Remove up to the opening fence’s indentation from content lines. Preserve other content literally, including blank lines; escape it for HTML.
- An unclosed fence continues to the end of its containing block or document. Fenced blocks may interrupt paragraphs.

# FEATURE: HTML Blocks

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Recognizes CommonMark block HTML and preserves it as raw output. |
| Depends On  | FEATURE-CLI.md |
| Provides    | HTML blocks |

## Questions

- None.

## Purpose

Recognize the seven CommonMark HTML block types and pass their lines through as raw HTML, ending each block according to its type’s termination rule.

## Behavior

- Start conditions allow up to three spaces of indentation.
- Types 1–5 end at their matching end condition; types 6–7 end at a blank line. A block also ends at the containing block or document boundary.
- Types 1–6 may interrupt a paragraph; type 7 may not.
- Preserve block content literally. Do not parse Markdown within an HTML block.

## Questions

- None.

## Purpose

Collect valid link reference definitions during block parsing so inline links and images can resolve them document-wide after block structure is complete.

## Behavior

- Definitions may occur before or after uses, inside containers, and in succession.
- Normalize labels by Unicode case folding, trimming surrounding spaces and line endings, and collapsing internal whitespace.
- Keep the first definition for a normalized label.
- A valid definition is removed from visible content; invalid candidates remain ordinary text.
- Parse destinations, optional titles, escapes, and permitted line continuations according to CommonMark 0.31.2.

# FEATURE: Paragraphs

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parses paragraph boundaries and renders paragraph inline content. |
| Depends On  | FEATURE-CLI.md |
| Provides    | paragraphs |

## Questions

- None.

## Purpose

Recognize paragraphs as sequences of nonblank lines that do not begin another block construct, then render their content as inline text.

## Behavior

- Join continuation lines with line endings.
- Ignore leading and trailing spaces or tabs around the paragraph’s raw content.
- Permit up to three leading spaces on the first line; four spaces begin indented code instead.
- Close a paragraph at a blank line or when a valid interrupting block begins.
