Planning Instructions

Delivery Shape

Build a command-line Markdown-to-HTML parser. It consumes UTF-8 Markdown on standard input and produces HTML on standard output through the root executable commonmark. Parse block structure first, including container blocks and link reference definitions; then parse inline content with the document’s reference definitions available. The supplied spec corpus and runner provide scoped implementation checks and a single terminal complete-suite check.

Test and Acceptance Strategy

Each parser story runs only the supplied examples for its named, example-owning section through sources/spec_tests.py --program ./commonmark --spec sources/spec.txt --pattern '<section heading>'. CLI-001 establishes the executable interface needed by those checks. CON-001 is the only terminal verification story and the only story with Suite: full; it runs sh sources/full_test.sh, captures and prints standard output and standard error, and asserts only result.returncode == 0. The same complete-suite result proves Sea Trial st-001.

Sequencing and Dependencies

Deliver CLI-001 first so scoped checks can invoke the parser. Implement block parsing before inline parsing. Within block parsing, establish leaf blocks and reference-definition collection before container and list behavior that depends on block boundaries. Inline link and image resolution depends on definitions collected across the document. Every parser story precedes CON-001. Stage the supplied scoring assets unchanged; do not invoke the full harness from scoped checks.

Source Conflicts and Gaps

No unresolved source conflicts. The parser language is not explicitly mandated; use Python as the narrow implementation choice consistent with the supplied Python runner and helper, and keep the required root executable interface. The instructions file is prompt-only; the conformance assets named by the instructions are staged for build and acceptance.
