Planning Instructions

Delivery Shape

Build a command-line Markdown-to-HTML parser. Its input is UTF-8 Markdown on standard input; its output is HTML on standard output. The implementation resolves block structure before parsing inline content, using document-wide link reference definitions during inline resolution. The supplied runner invokes the root-level executable against the staged specification examples.

Test and Acceptance Strategy

Each parser implementation story uses the supplied spec_tests.py runner with explicit selectors for the sections it owns. Select example-owning headings such as ATX headings and List items; do not select chapter headings that own no examples. Scoped checks never invoke sources/full_test.sh.

VERIFY-001 is the sole terminal verification story and depends on every parser implementation story. It runs sh sources/full_test.sh, prints captured stdout and stderr, and asserts only result.returncode == 0. Its acceptance check declares Suite: full and carries Sea Trials: st-001.

Sequencing and Dependencies

Implement the executable interface first, then block structure in the specification’s block-first order, followed by inline parsing. Inline links depend on the reference definitions collected during block parsing. The final verification story follows all implementation stories. Stage the runner’s imports and input files together: spec_tests.py, cmark.py, normalize.py, and spec.txt, as well as the supplied shell harness.
