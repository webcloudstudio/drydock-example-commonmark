# FEATURE: Indented Code

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Parse indented code blocks made of chunks of lines indented four or more columns and render them as pre and code elements. |
| Depends On  | FEATURE-ATX-Headings.md |
| Provides    | indented code block |
| Consumes    | block-type registry |

## Questions

- None.

## Purpose

Implement the Indented code blocks section of the spec as a registered block start rule.

## Rules

- A line with four or more columns of indentation (column-aware, tab stop 4), that is not blank and does not continue a paragraph, starts an indented code block.
- An indented code block cannot interrupt a paragraph. A non-blank line with fewer than four columns of indentation ends the block immediately.
- Chunks are separated by blank lines. Interior blank lines are kept in the content, with any indentation beyond four columns retained. Leading and trailing blank lines are not part of the block.
- Content is the literal lines minus four columns of indentation, including trailing spaces, and is HTML-escaped. It is never parsed as Markdown. There is no info string.
- It renders as `<pre><code>...</code></pre>` with a final line ending inside the code element.

## Reads

- Lines handed to the block engine.

## Writes

- Code block nodes in the block tree.

## Programmatic Acceptance

# FEATURE: Fenced Code

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Parse fenced code blocks delimited by backtick or tilde fences with info strings and indentation stripping. |
| Depends On  | FEATURE-Indented-Code.md |
| Provides    | fenced code block |
| Consumes    | block-type registry, shared unescape and entity helpers |

## Questions

- None.

## Purpose

Implement the Fenced code blocks section of the spec.

## Rules

- An opening fence is at least three consecutive backticks or tildes, with up to three spaces of indentation. Backtick and tilde fences cannot be mixed. The text after the fence is the info string, trimmed. For a backtick fence the info string must not contain a backtick; otherwise the line is not a fence (it is parsed as a paragraph with a code span).
- Content is all following lines until a closing fence of the same character, at least as long as the opening one, with up to three spaces of indentation and followed only by spaces or tabs. Closing fences have no info string.
- If the opening fence is indented by N spaces, up to N spaces of indentation are removed from each content line.
- An unclosed fence runs to the end of the document or the enclosing container.
- A fenced code block can interrupt a paragraph and needs no blank lines around it.
- The first word of the info string, after backslash unescape and entity decoding, becomes `class="language-WORD"` on the code element. Content is HTML-escaped and never parsed.

## Reads

- Lines handed to the block engine.

## Writes

- Code block nodes in the block tree.

## Programmatic Acceptance

# FEATURE: HTML Blocks

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Parse the seven kinds of HTML block and emit their lines as raw HTML. |
| Depends On  | FEATURE-Fenced-Code.md |
| Provides    | HTML block |
| Consumes    | block-type registry |

## Questions

- None.

## Purpose

Implement the HTML blocks section of the spec.

## Start and end conditions

After up to three spaces of indentation:

1. Line begins with `<pre`, `<script`, `<style` or `<textarea` (case-insensitive) followed by a space, tab, `>` or end of line. Ends at a line containing `</pre>`, `</script>`, `</style>` or `</textarea>` (case-insensitive, need not match the start tag).
2. Begins with `<!--`. Ends at a line containing `-->`.
3. Begins with `<?`. Ends at a line containing `?>`.
4. Begins with `<!` and an ASCII letter. Ends at a line containing `>`.
5. Begins with `<![CDATA[`. Ends at a line containing `]]>`.
6. Begins with `<` or `</` and one of the block-level tag names listed in the spec (case-insensitive), followed by a space, tab, end of line, `>` or `/>`. Ends before the next blank line.
7. Begins with a complete open tag (tag name not `pre`, `script`, `style` or `textarea`) or complete closing tag alone on the line, followed only by spaces and tabs. Ends before the next blank line.

## Rules

- If the first line also meets the end condition, the block is that single line. Types 1 to 5 include the line holding the end condition, with anything after the end tag.
- Blocks end at the end of the document or enclosing container if no end condition is met.
- Types 1 to 6 can interrupt a paragraph. Type 7 cannot.
- Lines are emitted unchanged and unescaped, with their original indentation. Content inside the block is never parsed as Markdown, and tags inside it never change parser state.

## Reads

- Lines handed to the block engine.

## Writes

- HTML block nodes in the block tree.

# FEATURE: Block Quotes

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Parse block quotes with marker handling, lazy continuation and the blank-line consecutiveness rule. |
| Depends On  | FEATURE-HTML-Blocks.md |
| Provides    | block quote container |
| Consumes    | block-type registry, lazy continuation check |

## Questions

- None.

## Purpose

Implement the Block quotes section of the spec as a registered container block.

## Rules

- A block quote marker is `>` with up to three spaces of indentation, optionally followed by one space of indentation. A following tab is treated column-aware, so a partly consumed tab leaves its remaining columns as content indentation.
- Continue rule: a line continues the quote if it has a marker. A line without a marker is a lazy continuation only if it would be paragraph continuation text of the deepest open paragraph. Headings, fences, thematic breaks, list items and indented code do not continue lazily.
- A blank line (or a line with only a marker) behaves as in the spec: a fully blank line ends the quote, so two quotes separated by a blank line stay separate.
- Block quotes can interrupt paragraphs and nest. Any number of leading `>` may be omitted on a lazy line of a nested quote.
- A quote can be empty. It renders as `<blockquote>` and `</blockquote>` with contents on separate lines.

## Reads

- Lines handed to the block engine.

## Writes

- Block quote nodes in the block tree.

# FEATURE: Setext Headings

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Parse setext headings, including multiline content and the precedence and laziness exclusions. |
| Depends On  | FEATURE-Block-Quotes.md |
| Provides    | setext heading block |
| Consumes    | paragraph block, thematic break block |

## Questions

- None.

## Purpose

Implement the Setext headings section of the spec.

## Rules

- A setext heading is one or more lines of paragraph text followed by an underline of `=` (level 1) or `-` (level 2) characters, with up to three spaces of indentation and only trailing spaces or tabs after. The underline cannot contain internal spaces.
- The text lines must be such that, without the underline, they would form a paragraph. The first line has at most three spaces of indentation.
- The underline applies to the whole accumulated paragraph, so multiple lines become one heading. The heading content is the paragraph's raw text with leading and trailing spaces and tabs removed, parsed as inlines. Trailing spaces or a backslash on the last content line are not a hard break.
- An underline of dashes takes precedence over a thematic break reading of the same line when it follows paragraph text. Without paragraph text it is a thematic break. A setext heading cannot be empty, so `====` alone is a paragraph.
- The underline cannot be a lazy continuation line of a container: after a quote or list item, an unmarked underline does not underline the container's paragraph.
- Link reference definitions already extracted from the paragraph's start do not become heading text.

## Reads

- Lines handed to the block engine; the open paragraph.

## Writes

- Heading nodes of level 1 or 2 in the block tree.

## Programmatic Acceptance
