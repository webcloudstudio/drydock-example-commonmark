# FEATURE: Links

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Implement the look-for-link-or-image procedure and the inline, full, collapsed and shortcut link forms with the destination and title grammar. |
| Depends On  | FEATURE-Emphasis.md, FEATURE-Link-Reference-Definitions.md |
| Provides    | look_for_link_or_image procedure, link destination and title grammar |
| Consumes    | delimiter stack, process_emphasis procedure, reference map, normalize_label |

## Questions

- None.

## Purpose

Implement the Links section of the spec following the Appendix "look for link or image" procedure. The `![` machinery is shared with images; image rendering belongs to the images story.

## Procedure

- On `]`, search the delimiter stack from the top for a `[` or `![` opener. If none is found, emit literal `]`. If the opener is inactive, remove it and emit literal `]`.
- Otherwise parse ahead for, in order: an inline link `(`destination, title`)`; a full reference `[label]`; a collapsed reference `[]`; a shortcut reference. References resolve through `normalize_label` and the reference map. A full reference whose label is not defined falls back to the shortcut form of the link text only if it is not followed by a label.
- On success, build the link node from the inlines after the opener, run `process_emphasis` with the opener as `stack_bottom`, and remove the opener. For a link (not an image), set every earlier `[` opener inactive, so links never nest.
- On failure, remove the opener and emit literal `]`.

## Grammar

- A destination is `<...>` with no line ending and no unescaped `<` or `>`, or a nonempty run with no space or control characters and balanced unescaped parentheses (at least three levels). An empty destination is allowed.
- A title is double-quoted, single-quoted or parenthesized, with backslash-escaped delimiters, and no blank line inside.
- Whitespace (spaces, tabs, at most one line ending) is allowed around the destination and title; destination and title must be separated by whitespace.
- A link label has at most 999 characters and no unescaped brackets. No whitespace is allowed between link text and a following label or `()`.
- Brackets inside link text must be balanced or backslash-escaped. Code spans, autolinks and raw HTML bind tighter than brackets.
- Destination and title go through the shared unescape and entity helpers. The href is percent-encoded for non-ASCII and unsafe characters with the shared helper (an existing `%XX` stays as is), and the href and title are HTML-escaped.

## Reads

- Inline text, the reference map.

## Writes

- Link nodes in the inline tree.

# FEATURE: Images

| Depends On  | FEATURE-Links.md |

## Questions

- None.

## Purpose

Implement the Images section of the spec on top of the shared link machinery, and gate the Emphasis, Links and Images corpus sections, which are all satisfiable once images exist.

## Rules

- An image description starts with `![` and follows the same bracket rules as link text, except it may contain links.
- All four forms apply: inline, full reference, collapsed and shortcut.
- Render `<img src="..." alt="..." />` with ` title="..."` only when a title exists. The src is percent-encoded and HTML-escaped like a link href.
- The alt value is the plain-text content of the description: emphasis, links and nested images are reduced to their text content (nested images contribute their own alt), code spans contribute their content, and the result is HTML-escaped.
- `\![foo]` is a literal `!` followed by a link; `!\[foo]` is literal text.

## Reads

- The inline tree built by the links story, the reference map.

## Writes

- Image nodes in the inline tree.

## Programmatic Acceptance

# FEATURE: Line Breaks and Text

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Implement hard line breaks, soft line breaks and plain textual content in inline parsing. |
| Depends On  | FEATURE-Images.md |
| Provides    | hard break and soft break inline nodes |
| Consumes    | inline scanner loop |

## Questions

- None.

## Purpose

Implement the Hard line breaks, Soft line breaks and Textual content sections of the spec.

## Rules

- A line ending preceded by two or more spaces, or by a backslash, that is not at the end of the block is a hard break, rendered as `<br />` followed by a line ending. The spaces or backslash are consumed. Leading spaces on the following line are dropped.
- Any other line ending inside a block is a soft break, rendered as a line ending. Spaces at the end of the line and at the start of the next line are removed.
- A hard-break marker at the end of a paragraph or heading is not a break: trailing spaces are dropped and a trailing backslash stays literal.
- Breaks work inside emphasis and link text. They are inert inside code spans (the line ending becomes a space) and inside raw HTML tags.
- All other characters are plain text. Internal spaces are preserved verbatim.

## Reads

- Inline text of paragraphs and headings.

## Writes

- Break and text nodes in the inline tree.

## Programmatic Acceptance

The Hard line breaks section has an ATX heading example, so it is gated in the tabs story. The checks here are bounded.

# FEATURE: Thematic Breaks

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Parse thematic breaks of three or more matching -, _ or * characters and render them as hr elements. |
| Depends On  | FEATURE-Line-Breaks-Text.md |
| Provides    | thematic break block |
| Consumes    | block-type registry |

## Questions

- None.

## Purpose

Implement the Thematic breaks section of the spec as a registered block start rule.

## Rules

- A thematic break is a line with up to three spaces of indentation, then three or more matching `-`, `_` or `*` characters, each optionally followed by any number of spaces or tabs. No other characters may appear on the line.
- All non-space characters must be the same. Four or more spaces of indentation is not a thematic break.
- A thematic break can interrupt a paragraph and needs no blank lines around it.
- When a line could be a thematic break or a list item, the thematic break wins. When a line of dashes could be a thematic break or a setext underline, the setext heading wins; that wiring is added by the setext story.
- It renders as `<hr />`.

## Reads

- Lines handed to the block engine.

## Writes

- Thematic break nodes in the block tree.

## Programmatic Acceptance

The corpus section needs lists, setext headings and emphasis, so it is gated in the lists story. The checks here are bounded.

# FEATURE: ATX Headings

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Parse ATX headings of levels 1 to 6 with optional closing sequences and render them as h1 to h6 elements. |
| Depends On  | FEATURE-Thematic-Breaks.md |
| Provides    | ATX heading block |
| Consumes    | block-type registry, inline parser hook |

## Questions

- None.

## Purpose

Implement the ATX headings section of the spec as a registered block start rule whose content is parsed as inlines.

## Rules

- An opening sequence of 1 to 6 `#` characters, preceded by up to three spaces of indentation, must be followed by a space, a tab or the end of the line. Seven or more `#` is not a heading, and `#hashtag` is not a heading.
- The content is stripped of leading and trailing spaces and tabs before inline parsing.
- An optional closing sequence of `#` characters must be preceded by a space or tab and followed only by spaces or tabs. Backslash-escaped `#` characters are not part of the closing sequence. A `#` run followed by other text is content.
- The heading level equals the number of opening `#` characters. A heading can be empty.
- An ATX heading can interrupt a paragraph and needs no blank lines around it.
- It renders as `<hN>content</hN>`.

## Reads

- Lines handed to the block engine.

## Writes

- Heading nodes in the block tree; inline content is parsed in phase 2.

## Programmatic Acceptance

The corpus section uses indented code and thematic break interactions, so it is gated in the lists story. The checks here are bounded.
