# ARCHITECTURE: CommonMark Parser

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Two-phase CommonMark 0.31.2 parser delivered as the stdin-to-stdout executable commonmark, with its module layout and technical decisions. |
| Depends On  | None |
| Provides    | mdparser package, mdparser.blocks, mdparser.inlines, mdparser.refs, mdparser.entities, mdparser.render, mdparser.cli |
| Consumes    | None |

## Questions

- None.

## Overview

The product is a single-process CLI. `./commonmark` reads UTF-8 Markdown from stdin and writes HTML to stdout. It is implemented in the Python package `mdparser` and follows the spec Appendix "A parsing strategy" directly.

- **Phase 1, block structure.** Lines are consumed one at a time. Each line is matched against the open blocks, then new block starts are looked for, then remaining text is added to the deepest open block. Link reference definitions are extracted when a paragraph closes and stored in one document-wide reference map.
- **Phase 2, inline structure.** The finished tree is walked. The raw text of paragraphs and headings is parsed into inlines with the delimiter-stack algorithms (look for link or image, process emphasis), using the reference map.
- **Rendering.** A renderer turns the tree into HTML. The conformance runner compares normalized HTML, so tag structure, entities and URL percent-encoding must match the spec examples.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`, which remains the decision of record.

| Technology | Where it applies |
|---|---|
| Python 3 | Implementation language for the whole package and the `commonmark` script. |
| Python standard library | The only runtime dependency set: `re`, `unicodedata`, `html.entities`, `sys`. |
| POSIX shell | The supplied `sources/full_test.sh` scoring entry point; it is staged, never authored. |

The Foundation Contract is: source root `./`, environment `.venv` created by `uv venv`, dependencies in `pyproject.toml` with a committed `uv.lock`, and `pytest -q` as the test command. The executable must also run under plain `python3` with no environment activated, because the supplied harness runs `./commonmark` directly.

## Modules

| Module | Responsibility |
|---|---|
| `commonmark` (root script) | Shebang entry point; puts its own directory on `sys.path` and calls `mdparser.cli.main`. |
| `mdparser.cli` | Byte intake, UTF-8 decoding with replacement, line-ending normalization, U+0000 replacement, output writing. |
| `mdparser.blocks` | Block tree, block-type registry (start, continue, close rules), per-line procedure, lazy continuation. |
| `mdparser.refs` | Reference map, link reference definition extraction, `normalize_label`. |
| `mdparser.inlines` | Inline scanner, delimiter stack, `process_emphasis`, look-for-link-or-image. |
| `mdparser.entities` | Entity and numeric character reference decoding, backslash unescape helper. |
| `mdparser.render` | HTML rendering, HTML escaping, URL percent-encoding. |

## Technical Decisions

- Named entities come from the standard library table `html.entities.html5`; only names ending in a semicolon are recognized.
- Label matching uses `str.casefold()` plus whitespace collapse.
- Unicode punctuation for flanking rules is classified with `unicodedata` general categories `P*` and `S*`.
- Soft line breaks render as a line ending.
- No public Markdown implementation is used or imported.
- Exit status is 0 for every input. Invalid UTF-8 is decoded with U+FFFD replacement. Diagnostics go to stderr only.

| File store | None. | None |
| External services | None. | None |
| Process I/O | `mdparser.cli` | `sys.stdin.buffer`, `sys.stdout.buffer`, `sys.stderr` |

# FEATURE: Executable

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | The commonmark executable reads UTF-8 Markdown on stdin, normalizes lines, and writes only HTML to stdout. |
| Depends On  | ARCHITECTURE.md |
| Provides    | ./commonmark |
| Consumes    | mdparser.cli |

## Questions

- None.

## Purpose

Deliver the executable `commonmark` at the application root. It takes no arguments.

## Trigger

A process runs `./commonmark` with Markdown on stdin.

## Sequence

1. Read all of stdin as bytes.
2. Decode as UTF-8 with U+FFFD replacement for invalid bytes.
3. Treat LF, CR and CRLF as line endings. Replace U+0000 with U+FFFD.
4. Pass the lines to the parser entry point in `mdparser.cli`. Until the block engine story lands this may be a placeholder that renders no blocks.
5. Write the rendered HTML to stdout as UTF-8 and exit 0.

## Interface

- File `commonmark` at the application root: python3 shebang, executable bit set, puts its own directory on `sys.path`, and does not need an activated virtual environment.
- stdin: UTF-8 Markdown. stdout: HTML only. stderr: diagnostics only.
- Exit status 0 for all input, including empty input and invalid UTF-8, with no traceback.
- `README.md` at the project root concisely describes the stdin/stdout interface. README content is not an acceptance criterion.

## Reads

- Standard input.

## Writes

- Standard output only. No files.

# FEATURE: Block Engine

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | The phase 1 block engine with an extensible block-type registry, paragraph and blank-line handling, and HTML rendering with escaping. |
| Depends On  | FEATURE-Executable.md |
| Provides    | block tree builder, block-type registry, paragraph renderer, HTML escaping helper, URL percent-encoding helper |
| Consumes    | ./commonmark, inline parser hook |

## Questions

- None.

## Purpose

Implement the per-line procedure from the spec Appendix, "Phase 1: block structure", and render paragraphs. Later block stories add start, continue and close rules to the registry without changing the loop.

## Sequence

For each line:

1. Walk the open blocks from the document down the last-child chain. Each block checks whether the line continues it. Unmatched blocks are not closed yet, because the line may be a lazy continuation.
2. Look for new block starts. If one is found, close the unmatched blocks, then create the new block under the last matched container.
3. Add the remaining text to the deepest open block. A line that is a lazy paragraph continuation is added to the open paragraph.

At end of input all open blocks are closed. Phase 2 then walks the tree and calls the inline parser hook for paragraph and heading content. The hook initially returns the escaped text.

## Rules

- A paragraph is a sequence of non-blank lines that is not another block. Its raw content strips initial and final spaces and tabs. Lines after the first may have any indentation.
- Blank lines separate paragraphs and are otherwise ignored, including at the start and end of the document.
- Column-aware indentation (tab stop 4) is computed in one shared helper, so later block stories reuse it.
- The renderer emits `<p>` elements, one line ending between blocks, and escapes `&`, `<`, `>` and `"` in text.
- The shared URL percent-encoding helper lives here and is reused by the link and autolink stories.

## Reads

- Lines produced by `mdparser.cli`.

## Writes

- HTML string returned to `mdparser.cli`.

## Programmatic Acceptance

The corpus sections Paragraphs and Blank lines need indented code, hard breaks and ATX headings, so they are gated in the tabs story and the terminal story. The checks here are bounded.

# FEATURE: Autolinks

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Parse URI autolinks and email autolinks inside angle brackets into links. |
| Depends On  | FEATURE-Block-Engine.md |
| Provides    | autolink inline construct |
| Consumes    | inline parser hook, URL percent-encoding helper |

## Questions

- None.

## Purpose

Implement the Autolinks section of the spec.

## Rules

- A URI autolink is `<`, a scheme, a colon, zero or more characters other than ASCII control characters, space, `<` and `>`, then `>`. A scheme is 2 to 32 characters: an ASCII letter followed by letters, digits, `+`, `.` or `-`.
- An email autolink is `<`, an address matching the HTML5 email regex given in the spec, then `>`. The href is `mailto:` followed by the address.
- The link text is the address as written, HTML-escaped. The href is percent-encoded for non-ASCII and unsafe characters (for example a backtick or backslash), with `&` escaped as `&amp;`.
- Backslash escapes are inert inside autolinks.
- Anything with a space, an empty body, a one-letter scheme, or no scheme or `@` stays literal text with `<` and `>` escaped.
- Autolinks bind as tightly as code spans and raw HTML; the first one found left to right wins.

## Reads

- Inline text of paragraphs and headings.

## Writes

- Link nodes in the inline tree.

# FEATURE: Raw HTML

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Parse raw inline HTML tags, comments, processing instructions, declarations and CDATA sections and pass them through unescaped. |
| Depends On  | FEATURE-Block-Engine.md |
| Provides    | raw inline HTML construct |
| Consumes    | inline parser hook |

## Questions

- None.

## Purpose

Implement the Raw HTML section of the spec.

## Grammar

- A tag name is an ASCII letter followed by letters, digits or hyphens.
- An attribute is whitespace (spaces, tabs, at most one line ending), an attribute name, and an optional value specification. An attribute name starts with a letter, `_` or `:` and continues with letters, digits, `_`, `.`, `:` or `-`.
- An unquoted value is nonempty and contains no whitespace, `"`, `'`, `=`, `<`, `>` or backtick. Quoted values use single or double quotes.
- An open tag is `<`, a tag name, attributes, optional whitespace (at most one line ending), an optional `/`, then `>`. A closing tag is `</`, a tag name, optional whitespace, then `>`, with no attributes.
- A comment is `<!-->`, `<!--->`, or `<!--` followed by text not containing `-->` and then `-->`. A processing instruction is `<?` to `?>`. A declaration is `<!`, an ASCII letter, then text up to `>`. CDATA is `<![CDATA[` to `]]>`.

## Rules

- A recognized tag is emitted unescaped and unchanged. Everything else is plain text with `<`, `>`, `&` and `"` escaped.
- Backslash escapes and entities are inert inside raw HTML, so the text is passed through byte for byte.
- Raw HTML binds as tightly as code spans and autolinks. It takes precedence over emphasis delimiters inside its attribute values.
- A line ending inside a tag is kept as written and never becomes a hard break.

## Reads

- Inline text of paragraphs and headings.

## Writes

- Raw HTML nodes in the inline tree.

## Programmatic Acceptance
