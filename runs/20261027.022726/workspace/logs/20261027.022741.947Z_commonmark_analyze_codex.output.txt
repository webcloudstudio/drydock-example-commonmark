Implementation stories use `spec_tests.py` with explicit selectors naming headings that own examples, covering each story’s complete scope. Do not invoke `full_test.sh` from scoped checks. DELIVERY-003 is the only terminal verification story with `Suite: full`; it runs `sh sources/full_test.sh`, prints captured stdout and stderr, and asserts only `result.returncode == 0`. It depends on all parser implementation stories and the executable delivery story. The stable Sea Trial `st-001` records the complete-suite requirement.

### Sequencing and Dependencies

Build the executable interface and block parsing before inline parsing. Collect reference definitions during block parsing before resolving links and images. Stories can be ordered by their supplied specification sections, with BLOCK-005 available before INLINE-004 and INLINE-005. The terminal verification comes last and uses the staged, read-only harness and its sibling assets. No database, migration, infrastructure, or external service dependencies are described.

### Source Conflicts and Gaps

The supplied instructions and specification establish the product, interface, implementation prohibition, and complete-suite acceptance. No conflicting product definitions or unresolved human-owned decisions are present. The source does not mandate a programming language; the stack proposal records Python as a conventional choice for this parser and harness context.
