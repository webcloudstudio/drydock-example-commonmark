# ARCHITECTURE: CommonMark Parser

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Defines the Python command-line parser structure and its block-first, inline-second parsing boundary. |

## Questions

- None.

## Purpose

The application is a Python command-line program rooted at `./commonmark`. It reads UTF-8 Markdown from standard input and writes rendered HTML to standard output.

## Components and boundaries

- The executable delegates parsing and rendering to original project code. It must not use a public Markdown implementation.
- The parser builds block structure before parsing inline content. Link reference definitions are collected during block parsing and made available to the inline phase.
- Block parsing owns paragraphs, headings, code blocks, HTML blocks, thematic breaks, block quotes, and lists. Inline parsing owns inline constructs such as escapes, code spans, emphasis, links, images, autolinks, raw HTML, and line breaks.
- The renderer converts the parsed document to HTML. The supplied conformance runner invokes `./commonmark` and compares normalized HTML with examples from the supplied specification.
- Runtime conformance assets are staged verbatim under `sources/`: `spec.txt`, `spec_tests.py`, `cmark.py`, `normalize.py`, and `full_test.sh`.

## Module ownership

| Boundary | Owner | Allowed access |
|-----------|-------|----------------|
| Parsing and rendering | Project parser modules | Internal parser and renderer interfaces |
| Configuration | None | No configuration store is specified |
| File store | None | No file store is specified |
| External services | None | No external service is specified |
| Conformance assets | `sources/` | Read-only runtime inputs for the supplied test harness |

## Technology Stack

| Technology | Use |
|------------|-----|
| Python 3 | CLI, parser, renderer, and project checks |
| Python standard library | Runtime implementation without third-party dependencies |
| POSIX shell | Supplied full-suite invocation |

# FEATURE: Thematic Breaks and ATX Headings

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parses CommonMark thematic breaks and ATX headings into HTML. |
| Depends On  | ARCHITECTURE.md |
| Provides    | thematic breaks, ATX headings |

## Questions

- None.

## Purpose

Implement thematic breaks and ATX headings as CommonMark 0.31.2 block constructs. Block structure takes precedence over inline syntax; heading contents are parsed by the inline parser.

## Behavior

- Recognize thematic breaks with up to three leading spaces and at least three matching `-`, `_`, or `*` markers, allowing spaces or tabs between markers and at the end.
- Recognize ATX headings with one through six opening `#` markers, up to three leading spaces, and the required whitespace or end-of-line after the opening sequence.
- Strip leading and trailing spaces or tabs from heading content and discard a valid optional closing sequence of unescaped `#` markers.
- Keep invalid heading candidates as paragraph content and render all recognized blocks using the CommonMark HTML forms.

| Description | Parses multiline setext headings and their underlines into HTML. |
| Depends On  | ARCHITECTURE.md |

## Questions

- None.

## Purpose

Implement level-one and level-two setext headings from paragraph lines followed by a valid underline.

## Behavior

- Recognize an underline made only of `=` or only of `-`, with up to three leading spaces and optional trailing spaces or tabs.
- Form a heading from one or more eligible paragraph lines followed by the underline; concatenate the lines and trim initial and final spaces or tabs before inline parsing.
- Do not form an empty heading. A line that would start another block construct cannot serve as setext heading text.
- Resolve an eligible dash underline as a setext heading when it follows paragraph content; otherwise preserve thematic-break precedence.

# FEATURE: Code Blocks

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parses indented and fenced code blocks as literal HTML code blocks. |
| Depends On  | ARCHITECTURE.md |
| Provides    | indented code blocks, fenced code blocks |

## Questions

- None.

## Purpose

Implement indented and fenced code blocks according to CommonMark 0.31.2. Code content is literal and is not processed as inline Markdown.

## Behavior

- An indented code block collects indented chunks, removes four spaces of indentation from nonblank lines, preserves content and blank lines, and cannot interrupt a paragraph.
- Fenced blocks begin with at least three matching backticks or tildes and up to three leading spaces. A closing fence uses the same marker, is at least as long, has up to three leading spaces, and is followed only by spaces or tabs.
- An unclosed fenced block continues to the end of its containing block or document.
- Remove up to the opening fence indentation from each content line. Use the first word of an info string as the code language class, escaping it for HTML attributes.
- Escape code text as HTML text while preserving its content.

# FEATURE: HTML Blocks

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Recognizes CommonMark HTML block types and passes their source through as raw HTML. |
| Depends On  | ARCHITECTURE.md |
| Provides    | HTML blocks |

## Questions

- None.

## Purpose

Implement all seven CommonMark HTML block types, preserving their source text and stopping at the appropriate end condition.

## Behavior

- Recognize start conditions after up to three spaces of indentation.
- For types one through five, continue through the matching end condition, or to the end of the containing block or document.
- For type six, continue until a blank line. For type seven, recognize complete open or closing tags on a line and continue until a blank line.
- Permit types one through six to interrupt paragraphs; type seven cannot interrupt a paragraph.
- Pass block contents through without inline parsing or escaping.
