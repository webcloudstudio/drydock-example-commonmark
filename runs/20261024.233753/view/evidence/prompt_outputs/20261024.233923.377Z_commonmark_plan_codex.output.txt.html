# FEATURE: Reference Definitions and Paragraphs

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Forms paragraphs and collects document-wide link reference definitions. |
| Depends On  | ARCHITECTURE.md |
| Provides    | link reference definitions, paragraphs |

## Questions

- None.

## Purpose

Form paragraphs from consecutive non-blank lines that are not interpreted as other block types. Collect link reference definitions during block parsing so inline links can resolve definitions anywhere in the document.

## Behavior

- Paragraph content is the raw text of its lines, with leading and trailing spaces or tabs removed before inline parsing. A paragraph cannot contain a blank line.
- Recognize link reference definitions with up to three spaces of indentation. Definitions may span lines as allowed by CommonMark 0.31.2 and may have an optional title.
- Definitions do not render as document content. Collect them across the whole document, including inside block quotes and list items.
- Normalize labels by Unicode case folding, trimming surrounding spaces, tabs, and line endings, and collapsing consecutive internal whitespace to one space.
- The first definition for a normalized label takes precedence.
- A link reference definition cannot interrupt a paragraph. Text that does not form a valid definition remains paragraph content.

| Version     | 20261024 V1 |
| Description | Parses CommonMark block quotes and their nested block content. |
| Depends On  | ARCHITECTURE.md |
| Provides    | block quotes |

## Questions

- None.

## Purpose

Parse block quotes as containers whose contents are parsed using the ordinary block rules.

## Behavior

- A block quote marker is `>` optionally preceded by up to three spaces; one following space or tab is part of the marker and is removed from the content.
- Consecutive marked lines form a quote. Blank marked lines can occur within it.
- Support lazy continuation only for lines that continue an existing paragraph. Do not apply laziness to block starts, code blocks, or other lines that require an explicit quote marker.
- Support nested block quotes and all block types inside quotes.
- A blank line separates consecutive block quotes. Quotes may interrupt paragraphs.

# FEATURE: Lists

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parses CommonMark bullet and ordered lists, including nesting and tightness. |
| Depends On  | ARCHITECTURE.md |
| Provides    | list items, lists and tightness |

## Questions

- None.

## Purpose

Parse bullet and ordered list items as containers, including nested blocks and the tight or loose rendering rules defined by CommonMark 0.31.2.

## Behavior

- Recognize bullet markers `-`, `+`, and `*`, and ordered markers of one to nine digits followed by `.` or `)`.
- Determine item continuation indentation from the marker width and the spaces after it; support the special rules for items beginning with indented code or a blank line.
- Support nested lists, lazy paragraph continuation, empty items, and list items containing any supported block type.
- Start a new list when list marker types differ. The ordered list start value comes from its first item.
- A list is loose when items are separated by blank lines or an item has block children separated by a blank line. Render paragraphs in loose lists with `<p>` tags and omit those tags for paragraphs in tight lists. Determine tightness independently for nested lists.

# FEATURE: Escapes and Character References

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parses CommonMark backslash escapes and HTML character references. |
| Depends On  | ARCHITECTURE.md |
| Provides    | backslash escapes, entity and numeric character references |

## Questions

- None.

## Purpose

Interpret backslash escapes and valid HTML entity and numeric character references in inline content according to CommonMark 0.31.2.

## Behavior

- A backslash escapes an ASCII punctuation character, rendering that character literally. A backslash before other characters remains literal.
- A backslash at the end of an inline line creates a hard line break.
- Recognize valid HTML5 named entities with semicolons, decimal references of one to seven digits, and hexadecimal references of one to six digits.
- Replace invalid Unicode code points and U+0000 with U+FFFD.
- Escape rendered text appropriately for HTML. References and escapes do not create block structure or replace structural Markdown markers.
- Do not interpret escapes or references inside code spans, code blocks, autolinks, or raw HTML.

# FEATURE: Code Spans

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parses and renders CommonMark inline code spans. |
| Depends On  | ARCHITECTURE.md |
| Provides    | code spans |

## Questions

- None.

## Purpose

Recognize matching backtick runs in inline content and render their contents as code.

## Behavior

- A code span opens with a run of one or more backticks and closes at the next run of exactly the same length.
- Convert line endings in code-span contents to spaces.
- Remove one leading and trailing space when both are present and the content is not entirely spaces.
- Preserve other content literally, including backslashes and character-reference syntax; escape it for HTML without interpreting Markdown inside the span.
- If no matching closing run exists, treat the opening backticks as literal text.
