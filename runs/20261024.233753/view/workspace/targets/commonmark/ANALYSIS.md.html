Planning Instructions

Delivery Shape

Build a command-line Markdown-to-HTML parser. It consumes UTF-8 Markdown on standard input and emits HTML on standard output through the root executable commonmark. The supplied specification and harness are staged under sources/. The implementation flow is block parsing, link reference collection, inline parsing, then HTML rendering. Scoped stories run their section examples; one terminal story runs the complete unfiltered suite.

Test and Acceptance Strategy

Run sources/spec_tests.py with explicit section selectors for each parser story's complete scope. The selectors must name example-owning headings. Do not invoke sources/full_test.sh from scoped checks. CONFORMANCE-002 is the sole terminal verification story, depends on every parser implementation story, and runs sh sources/full_test.sh with Suite: full. Its assertion checks only for a zero return code and prints captured standard output and standard error.

Sequencing and Dependencies

Implement block parsing before inline parsing. Complete reference-definition collection during block parsing so inline links can resolve document-wide references. The executable and README provide the callable interface. The terminal suite verification follows all parser implementation stories. Stage spec_tests.py, cmark.py, normalize.py, spec.txt, and full_test.sh verbatim; do not modify the supplied scoring assets.
