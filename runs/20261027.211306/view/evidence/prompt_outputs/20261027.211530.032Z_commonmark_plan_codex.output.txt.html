## Purpose and workflow

During block parsing, recognize a block quote marker after at most three spaces of indentation. The marker is `>` with at most one following space of indentation consumed; handle tabs using the specification's four-column tab stops. Add a block quote container to the document tree and parse its contents as blocks.

Continue open quote containers when their markers are present. A missing marker is permitted only for paragraph continuation text under the specification's laziness rule. A blank line without a marker closes the quote; an explicitly marked blank line remains inside it. Nest quotes recursively and close unmatched containers before starting a new block. Definitions found inside a quote contribute to the document-wide reference map.

For direct verification, expose `parse_blocks(source)` from `commonmark_parser.blocks`. It returns a document node whose `children` are ordered block nodes. Nodes expose `type`, `children`, and, for paragraphs, `literal` containing their unparsed inline source. A quote node has type `block_quote`, and a paragraph node has type `paragraph`. This interface exposes the block tree before inline parsing.

The complete Block quotes corpus section includes interactions with lists and inline parsing. The conformance integration story executes that complete section after those providers exist.

## Questions

- None.

## Purpose and workflow

Recognize bullet markers `-`, `+`, and `*`, and ordered markers of one to nine digits followed by `.` or `)`. Apply the specification's indentation rules, including marker width, one to four columns of following indentation, items starting with blank lines or indented code, tab stops, and lazy paragraph continuations. A thematic break takes precedence over a list item. An item interrupting a paragraph must be nonempty and an ordered list must start at one.

Group adjacent items only when their marker types match, including the bullet character or ordered delimiter. Preserve an ordered list's first start number. Parse nested block content and collect reference definitions document-wide. A list is loose when its items are separated by blank lines or an item directly contains blocks separated by a blank line; otherwise it is tight. The renderer uses that property to determine paragraph wrappers.

Extend `commonmark_parser.blocks.parse_blocks(source)` to return list and item nodes in the block tree. A list node exposes `type` equal to `list`, ordered `children` of type `item`, `ordered` as a boolean, `start` as the ordered start number, and `tight` as a boolean. Paragraph children retain their unparsed `literal`.

The complete List items and Lists corpus sections are executed by conformance integration after inline providers exist.

## Purpose and workflow

After the document block tree and reference map are complete, parse paragraph and heading text as inlines. A backslash escapes an ASCII punctuation character; otherwise it remains literal. Decode valid semicolon-terminated HTML5 named entities and valid decimal or hexadecimal numeric references under the specification's length and code-point rules. Replace invalid Unicode scalar values and U+0000 with U+FFFD. Unrecognized references remain text.

Represent ordinary text and soft line breaks in sequence. Remove spaces at the end of a soft-breaking line and at the beginning of the next line. Preserve the distinction between text parsing and literal contexts: escapes and references are not interpreted inside code spans, code blocks, autolinks, or raw HTML where the specification excludes them.

Expose `parse_inlines(source, references)` from `commonmark_parser.inlines`. It returns ordered inline nodes with `type` and, for text nodes, `literal`; a soft break has type `softbreak`. The reference map is supplied after block parsing, even where this increment does not use it.

## Purpose and workflow

Extend `commonmark_parser.inlines.parse_inlines(source, references)` to identify runs of `*` and `_` and classify potential openers and closers using the specification's Unicode whitespace and punctuation flanking rules. Apply the underscore restrictions and the rule of three using the original run lengths.

Use the appendix's delimiter-stack process: scan potential closers in input order, search backward for the nearest valid opener above the applicable lower bound, create an emphasis or strong node, consume one or two delimiter characters on each side, and remove intervening delimiters from the stack.
