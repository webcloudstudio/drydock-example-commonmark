## Structure and interfaces

The application root owns the Python project, `pyproject.toml`, committed `uv.lock`, the `.venv` environment created by `uv venv`, launchers in `bin/`, and the `pytest -q` test runner. Runtime code uses Python 3 and the standard library only.

Provide a `commonmark_parser` package with these integration interfaces:

- `commonmark_parser.render(markdown: str) -> str` accepts a complete document and returns HTML. The foundation supplies a callable integration point without claiming conformance.
- `commonmark_parser.blocks.parse_blocks(markdown: str) -> Document` produces a document tree. A `Document` has an ordered `children` sequence and a document-wide `references` mapping. Block nodes expose `kind`, `children`, and `literal`; headings also expose `level`.
- `commonmark_parser.inlines.parse_inlines(literal: str, references: dict) -> list` consumes raw paragraph or heading content and the completed reference map.

The block parser consumes lines in document order, maintains open container and leaf blocks, and collects reference definitions when paragraphs close. After the complete block tree and reference map exist, inline parsing processes the raw content of paragraphs and headings. Rendering walks the resulting structure to produce HTML. Preserve raw inline source until the inline phase. The later parser stories extend these interfaces.

Stage the supplied `spec.txt`, `spec_tests.py`, `cmark.py`, `normalize.py`, and `full_test.sh` verbatim under `sources/`. The runner imports its sibling helpers and accepts the candidate program and specification paths. `sources/INSTRUCTIONS.md` is planning context and is not a runtime asset.

## Technology Stack

Python 3 implements the parser and executable. The Python standard library supplies runtime facilities without third-party runtime dependencies. POSIX shell runs the supplied full-suite entry point.

# FEATURE: Paragraphs and Blank Lines

| Depends On | FEATURE-Executable.md |
| Provides | paragraph block parsing |

## Questions

- None.

## Behavior

`commonmark_parser.blocks.parse_blocks` returns a document whose paragraph nodes retain raw inline content in `literal`. A sequence of nonblank lines that does not start another block forms a paragraph. Remove initial and final spaces or tabs from the paragraph's raw content; remove leading indentation on continuation lines while preserving line endings and meaningful trailing spaces within the paragraph for later inline parsing. An indented continuation cannot start an indented code block in the middle of a paragraph.

Blank lines separate paragraphs and are ignored at document boundaries. Retain their role for later list tightness processing. The complete Paragraphs and Blank lines conformance sections run in the later conformance integration story once their interacting providers exist.

# FEATURE: Thematic Breaks

| Version | 20261027 V1 |

| Depends On | FEATURE-Paragraphs.md |
| Provides | thematic break parsing |
| Consumes | paragraph block parsing |

## Questions

- None.

## Behavior

Extend `commonmark_parser.blocks.parse_blocks` to produce nodes whose `kind` is `thematic_break`. A thematic break has up to three spaces of indentation and at least three matching `-`, `_`, or `*` markers, with only spaces or tabs between and after them. Different marker characters or other content make the line ineligible.

A thematic break may interrupt a paragraph. A valid setext underline takes precedence when it follows eligible paragraph content; a thematic break takes precedence over a list item interpretation. The setext and list stories complete those interactions. The complete Thematic breaks section runs in the later conformance integration story.

# FEATURE: ATX Headings

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Recognizes ATX heading blocks and retains their inline source. |
| Depends On | FEATURE-Paragraphs.md |
| Provides | ATX heading parsing |
| Consumes | paragraph block parsing |

## Questions

- None.

## Behavior

Extend `commonmark_parser.blocks.parse_blocks` to produce `heading` nodes with a numeric `level` and raw inline content in `literal`. An opening run contains one through six unescaped `#` characters, preceded by at most three spaces and followed by whitespace or the end of the line. The level is the opening run's length. Remove leading and trailing spaces or tabs from the content. An optional closing run of unescaped `#` characters is removed only when preceded by whitespace and followed solely by whitespace or the end of the line. Headings may be empty and may interrupt paragraphs.

Retain heading content for the subsequent inline phase. The complete ATX headings section runs in the later conformance integration story after interacting providers exist.
