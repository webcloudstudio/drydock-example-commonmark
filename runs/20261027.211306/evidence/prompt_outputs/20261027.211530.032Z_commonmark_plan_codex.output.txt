# FEATURE: Block Quotes

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |

| Depends On | FEATURE-Paragraphs.md, FEATURE-ThematicBreaks.md, FEATURE-ATXHeadings.md, FEATURE-SetextHeadings.md, FEATURE-IndentedCode.md, FEATURE-FencedCode.md, FEATURE-HTMLBlocks.md, FEATURE-ReferenceDefinitions.md |
| Provides | block quote parsing |
| Consumes | paragraph block parsing, thematic break parsing, ATX heading parsing, setext heading parsing, indented code block parsing, fenced code block parsing, HTML block parsing, document reference map |

## Questions

- None.

## Purpose and workflow

During block parsing, recognize a block quote marker after at most three spaces of indentation. The marker is `>` with at most one following space of indentation consumed; handle tabs using the specification's four-column tab stops. Add a block quote container to the document tree and parse its contents as blocks.

Continue open quote containers when their markers are present. A missing marker is permitted only for paragraph continuation text under the specification's laziness rule. A blank line without a marker closes the quote; an explicitly marked blank line remains inside it. Nest quotes recursively and close unmatched containers before starting a new block. Definitions found inside a quote contribute to the document-wide reference map.

For direct verification, expose `parse_blocks(source)` from `commonmark_parser.blocks`. It returns a document node whose `children` are ordered block nodes. Nodes expose `type`, `children`, and, for paragraphs, `literal` containing their unparsed inline source. A quote node has type `block_quote`, and a paragraph node has type `paragraph`. This interface exposes the block tree before inline parsing.

The complete Block quotes corpus section includes interactions with lists and inline parsing. The conformance integration story executes that complete section after those providers exist.

## Programmatic Acceptance

=== AC block-quote-lazy ===
Intent: A marked paragraph and its unmarked continuation belong to the same quote and retain their source text.

from commonmark_parser.blocks import parse_blocks

first = "alpha"
second = "continuation"
document = parse_blocks("> " + first + "\n" + second + "\n")
assert len(document.children) == 1
quote = document.children[0]
assert quote.type == "block_quote"
assert len(quote.children) == 1
paragraph = quote.children[0]
assert paragraph.type == "paragraph"
assert paragraph.literal.splitlines() == [first, second]
=== END AC block-quote-lazy ===

=== AC block-quote-nesting ===
Intent: Nested quote markers produce nested containers, and an unmarked blank line ends the quote.

from commonmark_parser.blocks import parse_blocks

inside = "inside"
outside = "outside"
document = parse_blocks("> > " + inside + "\n\n" + outside + "\n")
assert len(document.children) == 2
outer, paragraph = document.children
assert outer.type == "block_quote"
assert len(outer.children) == 1
inner = outer.children[0]
assert inner.type == "block_quote"
assert inner.children[0].type == "paragraph"
assert inner.children[0].literal == inside
assert paragraph.type == "paragraph"
assert paragraph.literal == outside
=== END AC block-quote-nesting ===

# FEATURE: Lists

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Parse list containers and their items. |
| Depends On | FEATURE-BlockQuotes.md |
| Provides | list block parsing |
| Consumes | block quote parsing, paragraph block parsing, thematic break parsing, ATX heading parsing, setext heading parsing, indented code block parsing, fenced code block parsing, HTML block parsing, document reference map |

## Questions

- None.

## Purpose and workflow

Recognize bullet markers `-`, `+`, and `*`, and ordered markers of one to nine digits followed by `.` or `)`. Apply the specification's indentation rules, including marker width, one to four columns of following indentation, items starting with blank lines or indented code, tab stops, and lazy paragraph continuations. A thematic break takes precedence over a list item. An item interrupting a paragraph must be nonempty and an ordered list must start at one.

Group adjacent items only when their marker types match, including the bullet character or ordered delimiter. Preserve an ordered list's first start number. Parse nested block content and collect reference definitions document-wide. A list is loose when its items are separated by blank lines or an item directly contains blocks separated by a blank line; otherwise it is tight. The renderer uses that property to determine paragraph wrappers.

Extend `commonmark_parser.blocks.parse_blocks(source)` to return list and item nodes in the block tree. A list node exposes `type` equal to `list`, ordered `children` of type `item`, `ordered` as a boolean, `start` as the ordered start number, and `tight` as a boolean. Paragraph children retain their unparsed `literal`.

The complete List items and Lists corpus sections are executed by conformance integration after inline providers exist.

## Programmatic Acceptance

=== AC list-items ===
Intent: Matching markers form one tight list with separate items whose paragraph text is preserved.

from commonmark_parser.blocks import parse_blocks

first = "alpha"
second = "beta"
document = parse_blocks("- " + first + "\n- " + second + "\n")
assert len(document.children) == 1
listing = document.children[0]
assert listing.type == "list"
assert listing.ordered is False
assert listing.tight is True
assert len(listing.children) == 2
assert all(item.type == "item" for item in listing.children)
assert [item.children[0].literal for item in listing.children] == [first, second]
=== END AC list-items ===

=== AC list-start-and-looseness ===
Intent: An ordered list retains its initial number and blank lines between items make it loose.

from commonmark_parser.blocks import parse_blocks

start = 4
first = "first"
second = "second"
document = parse_blocks(f"{start}. {first}\n\n5. {second}\n")
assert len(document.children) == 1
listing = document.children[0]
assert listing.type == "list"
assert listing.ordered is True
assert listing.start == start
assert listing.tight is False
assert [item.children[0].literal for item in listing.children] == [first, second]
=== END AC list-start-and-looseness ===

# FEATURE: Inline Text

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Parse ordinary inline text, escapes, character references, and soft line breaks. |
| Depends On | FEATURE-Lists.md |
| Provides | inline text parsing |
| Consumes | list block parsing, document reference map |

## Questions

- None.

## Purpose and workflow

After the document block tree and reference map are complete, parse paragraph and heading text as inlines. A backslash escapes an ASCII punctuation character; otherwise it remains literal. Decode valid semicolon-terminated HTML5 named entities and valid decimal or hexadecimal numeric references under the specification's length and code-point rules. Replace invalid Unicode scalar values and U+0000 with U+FFFD. Unrecognized references remain text.

Represent ordinary text and soft line breaks in sequence. Remove spaces at the end of a soft-breaking line and at the beginning of the next line. Preserve the distinction between text parsing and literal contexts: escapes and references are not interpreted inside code spans, code blocks, autolinks, or raw HTML where the specification excludes them.

Expose `parse_inlines(source, references)` from `commonmark_parser.inlines`. It returns ordered inline nodes with `type` and, for text nodes, `literal`; a soft break has type `softbreak`. The reference map is supplied after block parsing, even where this increment does not use it.

Conformance integration executes the complete Backslash escapes, Entity and numeric character references, Soft line breaks, and Textual content sections after interacting inline capabilities exist.

## Programmatic Acceptance

=== AC inline-escape ===
Intent: Escaped ASCII punctuation becomes literal text without retaining the escape marker.

from commonmark_parser.inlines import parse_inlines

punctuation = "!"
nodes = parse_inlines("\\" + punctuation, {})

=== END AC inline-escape ===

=== AC inline-soft-break ===
Intent: A regular line ending separates text nodes with a soft break while retaining their text.

from commonmark_parser.inlines import parse_inlines

first = "alpha"
second = "beta"

=== AC inline-numeric-reference ===

assert nodes[0].type == "text"

=== END AC inline-numeric-reference ===

# FEATURE: Code Spans

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Parse literal inline code delimited by matching backtick runs. |
| Depends On | FEATURE-InlineText.md |
| Provides | code span parsing |
| Consumes | inline text parsing |

## Questions

- None.

## Purpose and workflow

Extend `commonmark_parser.inlines.parse_inlines(source, references)` to recognize an opening backtick run and the next closing run of exactly the same length. Unmatched runs remain ordinary text. Normalize line endings inside a matched span to spaces. If the normalized content begins and ends with a space and is not entirely spaces, remove exactly one space from each end. Preserve all other content literally, including backslashes and character reference syntax.

Code spans bind more tightly than emphasis and link brackets. Their precedence relative to raw HTML and autolinks follows the specification when those providers are integrated. Return a node of type `code` with its normalized content in `literal`.

The complete Code spans corpus section is executed by conformance integration after interacting inline providers exist.

# FEATURE: Emphasis

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Parse emphasis and strong emphasis using delimiter runs. |
| Depends On | FEATURE-InlineText.md, FEATURE-CodeSpans.md |
| Provides | emphasis parsing |
| Consumes | inline text parsing, code span parsing |

## Questions

- None.

## Purpose and workflow

Extend `commonmark_parser.inlines.parse_inlines(source, references)` to identify runs of `*` and `_` and classify potential openers and closers using the specification's Unicode whitespace and punctuation flanking rules. Apply the underscore restrictions and the rule of three using the original run lengths.

Use the appendix's delimiter-stack process: scan potential closers in input order, search backward for the nearest valid opener above the applicable lower bound, create an emphasis or strong node, consume one or two delimiter characters on each side, and remove intervening delimiters from the stack. Continue with remaining delimiters and retain unmatched characters as text. Preserve the specified nesting and overlap precedence. Code spans bind more tightly; link, image, autolink, and raw HTML precedence is completed when those providers are integrated.

Emphasis nodes have type `em`, strong emphasis nodes have type `strong`, and each exposes ordered `children`. Text children expose `literal`.

The complete Emphasis and strong emphasis corpus section is executed by conformance integration after all interacting inline providers exist.

## Programmatic Acceptance

=== AC emphasis-basic ===
Intent: A matching single delimiter pair produces an emphasis node containing the supplied text.

from commonmark_parser.inlines import parse_inlines

content = "alpha"
